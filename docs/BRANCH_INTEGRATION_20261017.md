# 2026-10-17 브랜치 통합 기록

## 2026-10-18 추가 반영

`feature/fastapi-ui-integration`의 `d150775`까지 로컬 작업 트리에 반영했다.
기존 로컬의 Luna 기본 모델, RFP A/B 통합·토큰 배치(②), 파인튜닝 및 불필요 파일 정리는 유지했다.
사용자 요청에 따라 기존 파일 정리와 이 추가 작업을 `불필요한 파일 삭제 및 변경 내역 통합` 커밋으로 묶어 `main`에 반영한다. 로컬 파일을 기준으로 하며 환경변수·캐시 등 무시된 로컬 전용 파일은 포함하지 않는다.

- UI: 승인 이력 조회, 기술 입력 → 분석 준비 → 결과 확인 흐름, 명시적 분석 실행, 신규 특허번호 입력 제거.
- API: 지원 범위 조회, 입력 추출 재시도 제한, 단계별 안전한 오류 응답.
- NTIS/RFP: 보유기술과 하나 이상 연결되고 요청 목표 중 하나 이상을 충족하는 후보를 허용하며 충족·미충족 목표를 구분.
- 근거: 사용자 자기진술과 원문 근거 구분, RFP 인용을 같은 항목·페이지 내에서 검증.
- 검색: 기술 검색 어휘 중첩 기준 강화, 확장 RFP 질의가 너무 길면 기본 질의로 복귀.
- 실행: 요청 제한 시간·SDK 재시도·NTIS 추출 재시도를 설정으로 관리하고 실패 호출을 기록.

검증: 백엔드 단위 테스트 249개, 프런트엔드 테스트 72개, 프런트엔드 빌드와 린트 통과.
실제 유료 LLM 호출과 답변 품질 재평가는 수행하지 않았다. 따라서 위 통과 결과는 코드 동작 검증이며 검색·답변 품질 향상의 증거는 아니다.

현재 설정과 검증 근거는 [LLM 모델 통일 및 호출 방식 개선](LLM_CALL_OPTIMIZATION_20261018.md)을 참고하세요.

## 충돌과 보완

- API/UI 병합은 파일 충돌 없이 완료됐다. 파인튜닝 실험 파일과 로컬 Gap 분석 삭제가 유지됐다.
- NTIS/RFP 이력 병합에서 `tests/test_orchestrator.py` 한 곳이 충돌했다.
  예전 `policy_runner` 주입을 복구하지 않고 main의 법령 검색 제거를 유지했다.
  이 병합은 최종 파일 내용을 추가로 변경하지 않았다.
- API 의존성 목록이 없어 로컬에서 API 테스트를 불러오지 못했다.
  `requirements-api.txt`를 추가하고 프런트엔드 실행 안내를 실제 API 흐름에 맞췄다.
- Windows CRLF에서도 프런트엔드 포커스·스크롤 검증이 동작하도록 테스트 정규식을 수정했다.
- 삭제된 local Gap 분석을 참조하며 건너뛰던 테스트 3개를 현행 LLM 전용 경로에 맞췄다.
  저장 상태 재사용, Gap 실패 시 답변 생성 중단, 제거된 local 모드 거부를 확인한다.
