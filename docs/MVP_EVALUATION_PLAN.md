# MVP Ground Truth 평가 계획

## 현재 확인 결과

저장소에는 `data/evaluation/.gitkeep`만 있고, 기존 5문항 Ground Truth의 질문·정답·판정 기준은
추적되어 있지 않다. 따라서 이 변경에서는 정확도·재현율·통과율을 계산하지 않는다.

## 필요한 입력

각 문항에 다음을 포함한 버전 관리 파일(JSONL 권장)이 필요하다.

- `question_id`, 원문 질문, 보유기술 A, 요청 목표 B(복수 허용)
- 기대 Technology/NTIS/RFP 문서 ID와 허용 가능한 대체 문서 ID
- 목표별 `matched_goals` 기대값
- RFP 요구사항 인용문과 페이지·요구항목 경계
- 기대 Gap 라벨과 라벨 근거, 허용하지 않을 과장 문장

## 평가 절차

1. 인덱스·데이터 버전과 모델·프롬프트·설정 지문을 고정한다.
2. 유료 호출 전에 fake LLM 계약 테스트로 positive, empty, multi-goal, 고득점 오탐,
   페이지 경계 위조 인용, 단계 예외, projection 실패를 실행한다.
3. 승인된 예산에서만 실제 LLM 5문항을 실행하고 호출 수·토큰·비용·시간을 기록한다.
4. 문서 검색은 Recall@K/MRR, 목표 매핑은 목표별 precision/recall, 인용은 정확 일치와
   페이지·항목 경계 준수율, Gap은 문항별 라벨 일치와 과장 금지 위반 수로 평가한다.
5. 실패는 검색 실패, 관련성 gate 실패, 인용 검증 실패, Gap 정렬 실패, 답변 투영 실패로 분리한다.

## 완료 기준

5문항이 저장소에 들어오기 전에는 `NOT EVALUATED`로 유지한다. 문항 수가 작으므로 집계 수치와
함께 문항별 결과·실패 원인을 반드시 공개하며, fake/mock 통합 통과를 실제 LLM 정확도로 표현하지 않는다.
