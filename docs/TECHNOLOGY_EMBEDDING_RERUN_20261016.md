## 현재 데이터 확인

Supabase의 `technology` 문서·청크를 읽기 전용 트랜잭션으로 다시 내려받았습니다.
현재 설정의 청킹 코드로 591개 문서 payload에서 1,773개 청크를 다시 만들었고, 현재 DB 및 이전 실험의 ID·본문과 모두 일치했습니다.
문서 원문도 이전 실험과 같습니다. 따라서 기존 분할과 학습·평가 질문을 재사용합니다.
운영 데이터나 임베딩을 재적재하지 않습니다.

## 비교 조건

- 기본 모델: `dragonkue/BGE-m3-ko`, revision `7074d66aa46562342193ca4feb3d89bf9dad71b4`.
- 이전 모델: 기술나눔의 `lora_pilot_v1/adapter_epoch_2`.
- 새 모델: 기본 모델에서 기술나눔 학습 데이터만으로 새로 학습. RFP 어댑터에서 이어 학습하지 않습니다.
- 학습 데이터: 기존 검증을 통과한 688개 예제. 현재 원문의 양성·음성 근거, Train 포함 여부, 양성·음성 그룹 분리를 다시 검사합니다.
- Validation: 334개 질문. MRR@10으로 2 epoch 중 하나를 고르고 동률이면 이전 epoch을 택합니다.
- Test: 사용자 질문 10개와 확장 질문 154개를 각각 평가합니다. 확장 질문에는 사용자 질문 10개가 포함됩니다.
- 학습 seed 20261016, LoRA rank 8/alpha 16/dropout 0.05, query/value 대상, 학습률 2e-5, weight decay 0.01, 누적 8, temperature 0.05.
- 명시적 음성 예제를 사용한 softmax 손실이며 in-batch negatives는 사용하지 않습니다.
- 학습 최대 384 token, 평가 최대 8,192 token. GPU FP16 autocast, 벡터는 FP32로 정규화한 뒤 정확한 코사인 검색을 수행합니다.
- 전체 1,773개 청크에서 문서별 최고 점수로 591개 기술의 순위를 매깁니다. 같은 그룹이라도 자동으로 동일 정답 문서로 병합하지 않습니다.
- BM25·리랭킹·LLM 판정·최종 생성 답변은 이 임베딩 단독 평가에 포함하지 않습니다.

## 해석의 한계

Train/Validation과 추가 144개 Test 질문은 사람이 검수하지 않은 합성 데이터입니다.
Test는 이전에 결과를 본 재사용 세트이며, 새 미공개 Test의 일반화 성능을 의미하지 않습니다.
앞서 확인된 추가 정답 후보 4건은 `label_review_flags.json`에 보존합니다. 검수 전에는 기존 정답 라벨을 임의로 바꾸거나 해당 질문을 제외하지 않습니다.
작은 지표 변화는 학습 seed, 수치 정밀도, 관련 정답 누락의 영향일 수 있습니다.

## 실행과 산출물

`python -X utf8 -m app.scripts.retrain_technology_embedding prepare|train|evaluate`의 세 단계를 차례대로 실행합니다.
`prepare` 전에 `source_snapshot/`에 읽기 전용 DB 사본을 준비해야 합니다.
이미 생성된 학습 체크포인트와 결과를 덮어쓰지 않습니다. 새 실험에는 다른 `--output` 폴더를 사용하세요.

최종 비교 수치는 실험 폴더의 `report.md`와 `comparison.json`, 학습 내역은 `history.json`, 재로드 검증은 `reload_verification.json`에 저장합니다.
추가 LLM API 호출, Supabase 수정, 운영 모델 교체는 수행하지 않습니다.
