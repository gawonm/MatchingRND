## 검증과 해석

- 각 방법은 새 프로세스에서 1회 실행했다. 앱의 LLM 디스크 캐시는 방법별 빈 폴더로 분리했다.
- 전체 응답 시간은 입력 해석 시작부터 최종 답변 생성·저장까지다. Python import 시간은 제외한다.
- 실제 HTTP 요청과 API usage를 계측했다. 출력 토큰에는 API가 보고한 reasoning 토큰도 포함된다.
- API의 캐시 읽기·쓰기 토큰을 반영한 추정 비용이다. 청구서나 계정별 계약 비용이 아니다.
- USD/100만 토큰: 입력 0.20, 캐시 읽기 0.02, 캐시 쓰기 0.25, 출력 1.20.
- 입력 272,000토큰 초과 요청은 입력 단가 2배·출력 단가 1.5배로 계산한다.
- 단가 출처: [OpenAI 공식 요금표](https://developers.openai.com/api/docs/pricing).
- 단일 질문·단일 실행 비교이므로 속도나 정확도의 일반화된 보장은 아니다.
- 후보 수·원문을 사전에 줄이지 않았다. 상위 검색 순위부터 목표 수에 도달하거나 후보가 소진될 때까지 판정한다.
- 모델 응답과 검색 확장의 변동도 전체 지표에 영향을 줄 수 있다. 테스트 통과가 추천 정확도를 입증하지는 않는다.

입력 해석 일치: True.
RFP 검색 질의 일치: False.

NTIS 분석 응답이 달라 RFP 검색 질의·후보 집합도 완전히 같지 않다. 따라서 전체 감소율을 RFP 코드 변경만의 인과 효과로 해석하면 안 된다.

## 채택한 설정

**기본값은 개선 1(A/B 동시 판정·문자 기준 배치)로 유지한다.**
토큰 기준 배치는 실험 옵션으로 남겼다. 이번 실행에서 기준·개선 1이 제외한
`10RT급 히트펌프-데시컨트 하이브리드 냉·난방/제습 통합 시스템 기술 개발`을 추가로 통과시켰다.
토큰 배치판은 요청기술 B의 reason에서 터빈 발전이 포함되지 않는다고 설명하면서도 similar를 부여했다.
인용문 원문 일치는 통과했지만, 요청한 터빈 발전 연동 기능의 근거는 부족하다.
호출 수 감소만으로 정확도가 유지됐다고 결론 내리지 않고, 이 설정을 기본값으로 채택하지 않았다.
